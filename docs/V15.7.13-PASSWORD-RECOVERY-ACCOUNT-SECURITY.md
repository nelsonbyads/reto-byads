# DadoFit V15.7.13 — Password Recovery & Account Security

## Objetivo

Cerrar el hueco funcional de recuperación y cambio de contraseña usando Supabase Auth, sin exponer contraseñas ni crear almacenamiento paralelo de credenciales.

## Reglas de seguridad

- DadoFit nunca muestra ni recupera la contraseña actual de una cuenta Supabase.
- Gym, Marca, Coach, Owner, Admin y SuperAdmin no pueden leer contraseñas.
- La recuperación se inicia desde el login y se procesa por correo mediante Supabase Auth.
- La respuesta del formulario de recuperación es neutral: no confirma si un correo existe.
- La nueva contraseña debe tener entre 8 y 72 caracteres.
- La recuperación usa una sesión temporal originada por el enlace de Supabase.
- Después de guardar la contraseña desde recuperación, DadoFit cierra la sesión temporal y obliga a iniciar sesión nuevamente.
- El cambio de contraseña desde Perfil exige verificar primero la contraseña actual.
- La nueva contraseña no puede ser idéntica a la actual en el flujo autenticado.

## Flujo de recuperación

1. Login -> `¿Olvidaste tu contraseña?`.
2. `/forgot-password` solicita el correo.
3. DadoFit llama `supabase.auth.resetPasswordForEmail` usando como retorno `${window.location.origin}/reset-password`.
4. El usuario abre el correo enviado por Supabase.
5. Supabase crea la sesión de recuperación y DadoFit habilita `/reset-password`.
6. El usuario define y confirma la nueva contraseña.
7. DadoFit llama `supabase.auth.updateUser({ password })`.
8. La sesión temporal se cierra.
9. El usuario vuelve al login e ingresa con la contraseña nueva.

## Cambio de contraseña desde Perfil

En `/profile` se agregó `Seguridad > Contraseña de tu cuenta`.

El usuario debe indicar:

- contraseña actual;
- nueva contraseña;
- confirmación.

DadoFit verifica la contraseña actual con `signInWithPassword` antes de llamar `updateUser`.

## Configuración obligatoria en Supabase

No hay migración SQL en esta versión. Sí hay una configuración de Auth necesaria.

En Supabase Dashboard:

`Authentication -> URL Configuration -> Redirect URLs`

agregar al menos:

- `http://localhost:5175/reset-password`
- la URL real de producción terminada en `/reset-password` cuando exista.

Si Vite se levanta en otro puerto, ese origen también debe estar permitido o el correo no podrá volver a la ruta correcta.

## QA recomendado

### Recuperación

1. Cerrar sesión.
2. Login -> `¿Olvidaste tu contraseña?`.
3. Enviar el correo de un usuario real de prueba.
4. Confirmar que la UI siempre muestra el mensaje neutral.
5. Abrir el correo y entrar al enlace.
6. Confirmar que `/reset-password` permite crear una contraseña nueva.
7. Probar confirmación distinta: debe bloquear.
8. Probar menos de 8 caracteres: debe bloquear.
9. Guardar una contraseña válida.
10. Confirmar que la sesión de recuperación termina y el login acepta la nueva contraseña.
11. Confirmar que la contraseña anterior ya no inicia sesión.

### Perfil

1. Iniciar sesión con una cuenta Supabase.
2. Perfil -> Seguridad.
3. Probar una contraseña actual incorrecta: debe bloquear.
4. Probar nueva contraseña igual a la actual: debe bloquear.
5. Probar confirmación distinta: debe bloquear.
6. Cambiar a una contraseña válida.
7. Cerrar sesión e iniciar con la nueva contraseña.

## No incluido

- 2FA/MFA.
- Login social.
- Historial de contraseñas.
- Expulsar todas las sesiones remotas después de un cambio autenticado.
- Gestión administrativa de credenciales.

Estas capacidades pueden tratarse en una fase posterior de seguridad de cuenta.
