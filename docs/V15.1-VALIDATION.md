# DadoFit V15.1 — Validación

## Instalación

1. Copiar/reemplazar los archivos del ZIP en la raíz del proyecto.
2. Ejecutar:

```bash
npx supabase migration list
npx supabase db push
node scripts/check-supabase.mjs
npm test
npm run build
npm run dev
```

Schema esperado:

```text
v15.1-reward-fulfillment-coupon-inventory
```

## Caso A — Header compacto

1. Entrar como Perfil Personal.
2. Abrir `/app`.
3. Reducir la ventana aproximadamente a 900–1100 px.

Esperado:

- Entrenar visible
- Retos visible
- Premios visible
- botón `Más` visible
- Gymbros/Squads/Organizaciones/Patrocinados dentro de `Más`
- Workspace, notificaciones, tema y usuario siguen operables
- sin texto solapado ni header apretado

## Caso B — Código compartido

1. Entrar como Owner/Admin Nike.
2. `/rewards/manage`.
3. Crear/editar una oferta con:
   - Tipo de entrega: Código digital
   - Modo: Un código para todos
   - Código: `DADOFIT20`
4. Publicar.
5. Canjear como Gymbro.

Esperado:

- se descuentan DC;
- el Gymbro recibe `DADOFIT20`;
- además ve una referencia `DF-...` distinta para auditoría;
- botón Copiar funciona.

## Caso C — Pool de códigos

Crear una oferta con:

```text
NIKE-A001
NIKE-A002
NIKE-A003
```

Esperado en Partner:

```text
3 cargados
3 disponibles
0 asignados
```

Canjear con un Gymbro.

Esperado:

```text
2 disponibles
1 asignado
```

El Gymbro recibe uno de los tres códigos. Un segundo Gymbro recibe otro diferente.

## Caso D — Sin códigos

Intentar publicar una oferta `code_pool` sin códigos disponibles.

Esperado: publicación bloqueada y ningún cambio económico.

## Caso E — URL de redención

1. Tipo: Beneficio digital.
2. Modo: URL / página de redención.
3. Configurar una URL `https://...`.
4. Publicar y canjear.

Esperado:

- la URL NO se muestra en el catálogo antes del canje;
- después del canje aparece `Abrir página de redención`;
- los DC se descuentan una sola vez.
