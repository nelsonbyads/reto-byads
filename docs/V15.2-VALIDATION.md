# DadoFit V15.2 — Validación

## Instalación

1. Extraer el ZIP sobre la raíz de `reto-byads` y aceptar reemplazos.
2. Ejecutar:

```bash
npx supabase migration list
npx supabase db push
node scripts/check-supabase.mjs
npm test
npm run build
npm run dev
```

Schema esperado:

```text
v15.2-reward-qr-fulfillment
```

## Prueba A — Premio presencial

1. Entrar como Owner/Admin de Titanes, Nike u otra organización verificada.
2. Ir a `Ofertas`.
3. Crear un premio con `Tipo de entrega = Canje presencial` o `Producto físico`.
4. Publicarlo.
5. Entrar como Gymbro personal con saldo suficiente.
6. Ir a `Premios` y canjear.

Esperado:

- Se descuentan los DC una sola vez.
- En `Mis canjes` aparece estado `issued`.
- Aparece `Mostrar QR de entrega`.
- El Gymbro conserva la referencia `DF-...` como fallback manual.

## Prueba B — Validación por partner

1. Como Owner/Admin, abrir `/rewards/validate` o usar `Validar canjes` desde Ofertas.
2. Buscar la referencia `DF-...` del Gymbro o abrir el link contenido en el QR.
3. Validar que se muestren premio, Gymbro, costo DC, referencia y vigencia.
4. Agregar una nota opcional y pulsar `Confirmar entrega`.

Esperado:

- Estado pasa de `issued` a `redeemed`.
- Se registra fecha de entrega y actor.
- El canje sale de la cola pendiente.
- El Gymbro recibe notificación de premio entregado.
- Su historial muestra `Entregado` y deja de mostrar QR activo.

## Prueba C — Doble validación

Volver a abrir el mismo QR/referencia.

Esperado:

- DadoFit muestra que ya fue entregado.
- No genera una segunda entrega ni altera DC.

## Prueba D — Seguridad entre organizaciones

1. Crear/canjear una oferta de Organización A.
2. Intentar buscarla desde Owner/Admin de Organización B.

Esperado:

- Backend bloquea la operación con `this redemption belongs to another provider`.

## Prueba E — Acceso

- Owner/Admin: puede validar.
- Coach/Member: no puede validar.
- Perfil personal: puede abrir el link, pero debe cambiar a un workspace Gym/Marca donde sea Owner/Admin.
