# DadoFit V15.7.13.1 — Recovery Session Guard Hotfix

## Hallazgo QA

Al abrir un enlace válido de recuperación, Supabase intercambia el enlace por una sesión autenticada temporal. En V15.7.13 esa sesión permanecía activa mientras el usuario estaba en `/reset-password`.

Si el usuario no definía una contraseña nueva, abandonaba el flujo y navegaba a `Solicitar otro enlace`, la aplicación podía detectar esa sesión como una sesión normal y redirigir al perfil/workspace. Esto permitía entrar a DadoFit sin haber completado el cambio de contraseña, aunque el acceso provenía de haber demostrado posesión del enlace de recuperación.

## Regla corregida

Una sesión originada por `PASSWORD_RECOVERY` es ahora **recovery-only** hasta que ocurra una de estas acciones:

1. El usuario guarda una contraseña nueva. La sesión temporal se cierra y vuelve al login.
2. El usuario cancela la recuperación. La sesión temporal se cierra y vuelve al login.
3. El enlace/sesión ya no es válido y el usuario solicita otro enlace. Primero se cierra cualquier sesión de recuperación residual.

Mientras `recoveryMode` esté activo, las rutas privadas y el redirect principal fuerzan `/reset-password`; no pueden abrir `/app`, `/profile`, workspaces ni otras áreas autenticadas.

## Persistencia del guard

El estado recovery-only se marca en `localStorage` para que cerrar/reabrir la pestaña no convierta accidentalmente la sesión temporal en una sesión normal. El marcador se elimina al completar, cancelar o cerrar sesión.

## QA recomendado

1. Solicitar recuperación y abrir el enlace.
2. En `/reset-password`, no guardar contraseña.
3. Intentar abrir manualmente `/app` o `/profile`: debe volver a `/reset-password`.
4. Pulsar `Cancelar y volver`: debe cerrar la sesión temporal y mostrar login sin estar autenticado.
5. Solicitar otro enlace y abrirlo.
6. Si el flujo muestra `Solicitar otro enlace` por enlace inválido/expirado, pulsarlo: debe cerrar cualquier sesión temporal antes de abrir `/forgot-password`.
7. Completar recuperación con contraseña nueva: debe cerrar sesión y exigir login con la nueva contraseña.
8. Confirmar que la contraseña anterior ya no inicia sesión.
