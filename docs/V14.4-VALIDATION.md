# Validación V14.4

## 1. Aplicar migración

```bash
npx supabase migration list
npx supabase db push
node scripts/check-supabase.mjs
```

Esperado:

`Schema: v14.4-ad-analytics-click-tracking`

## 2. Validar compilación

```bash
npm test
npm run build
npm run dev
```

## 3. Generar una impresión
1. Iniciar sesión como usuario normal.
2. Abrir `/app`, `/challenges` o `/gymbros` en desktop.
3. Dejar visible al menos 1 segundo una campaña activa.
4. Entrar como SuperAdmin en `/admin/ads`.
5. El KPI **Impresiones** debe ser mayor que 0.

## 4. Generar un clic identificado
1. Volver a una página con pauta usando un usuario autenticado, por ejemplo Nelson Bro1.
2. Hacer clic en una campaña que tenga `Destino URL`.
3. Volver a `/admin/ads` y pulsar **Actualizar**.
4. Debe incrementarse **Clics**.
5. En **Quién interactuó** debe aparecer el nombre/email del usuario, campaña, ruta, dispositivo, placement y fecha.

## 5. Validar CTR
CTR = clics / impresiones × 100.
La tabla **Desempeño comercial** debe mostrar las métricas separadas por campaña.

## 6. Validar rotación
Con dos campañas activas en el mismo placement:
- cada campaña debe acumular sus propias impresiones/clics;
- el cambio de valla no debe alterar el layout;
- los eventos deben asociarse al `campaign_id` realmente visible.

## 7. Seguridad
Un usuario normal no debe poder ejecutar los RPC administrativos de analítica.
La identidad de clic se deriva en backend con `auth.uid()`.

## Nota de privacidad para producción
Antes del lanzamiento comercial conviene actualizar Política de Privacidad/Cookies para describir expresamente esta medición publicitaria first-party y definir el consentimiento requerido según la jurisdicción y las herramientas de terceros que se conecten posteriormente.
