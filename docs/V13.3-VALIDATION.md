# DadoFit V13.3 - UX/UI Polish + Brand Governance

## Objetivo

Este milestone mejora la coherencia visual de DadoFit y convierte el workspace de Marca en un centro operativo con trazabilidad y control de calidad.

## Incluye

- Header global compacto y coherente con `/app`.
- Navegación contextual Personal / Gym / Marca.
- Selector de workspace compacto.
- Apariencia dentro de un menú en lugar de tres botones permanentes.
- Menú de usuario con perfil y logout.
- Perfil personal reorganizado.
- Dashboard de Marca con KPIs operativos.
- Histórico de revisiones.
- Doble validación opcional por campaña.
- Cola de auditoría.
- Segundo revisor obligatorio distinto del primero.
- Recompensas retenidas hasta la segunda aprobación cuando la política está activa.
- Auditoría rechazada permite corregir y reenviar evidencia.
- Historial de `challenge_reviews` permanece inmutable.

## Instalación

Extraer el ZIP sobre la raíz del repositorio.

Luego:

```bash
npx supabase migration list
npx supabase db push
node scripts/check-supabase.mjs
npm test
npm run build
npm run dev
```

Health esperado:

```text
Schema: v13.3-brand-governance-audits
```

## Validación funcional recomendada

### A. UX/UI

1. Abrir `/profile`.
2. Confirmar que workspace, tema y usuario ya no aparecen como tres bloques desconectados.
3. Cambiar entre Personal, Gym y Marca desde el selector compacto.
4. Cambiar tema desde el icono de apariencia.
5. Confirmar que la navegación contextual cambia según el workspace.
6. Revisar desktop y mobile.

### B. Dashboard Marca

1. Entrar como Nike y abrir `/workspace`.
2. Confirmar KPIs: campañas activas, retos activos, por revisar, por auditar, aprobados y DC entregados.
3. Confirmar sección `Actividad reciente`.
4. Abrir `Control & Auditoría`.

### C. Histórico

1. Abrir `/brand-audit`.
2. Verificar que aparecen revisiones históricas ya existentes como `Revisión inicial`.
3. Probar filtros: Todas / Revisión inicial / Auditoría.

### D. Doble validación

Usar una campaña nueva o una campaña pausada.

1. Confirmar que la Marca tiene al menos **2 Owners/Admins activos**.
2. En `/brand-audit`, activar `Doble validación`.
3. Activar la campaña y publicar un Branded Challenge.
4. Un Gymbro se une, sube evidencia y envía.
5. Reviewer A (Owner/Admin) aprueba desde Campañas.
6. Resultado esperado:
   - participante pasa a `pending_audit`;
   - NO recibe DadoCoins ni XP todavía;
   - aparece en `Cola de auditoría`;
   - la revisión inicial queda en histórico.
7. Reviewer B (Owner/Admin distinto) abre `/brand-audit`.
8. Confirmar aprobación.
9. Resultado esperado:
   - participante queda `approved`;
   - recompensa se entrega una sola vez;
   - auditoría queda registrada en histórico.

### E. Protección de doble validación

Con el mismo usuario que hizo la primera revisión, intentar auditar.

Resultado esperado:

```text
the second validation must be performed by a different reviewer
```

### F. Auditoría rechazada

1. Reviewer A hace primera aprobación.
2. Reviewer B rechaza la auditoría con comentario.
3. Participante debe volver a estado `rejected`.
4. Puede corregir evidencia y volver a enviar.
5. Las revisiones anteriores deben seguir visibles en histórico.

## Regresión

Las campañas existentes conservan:

```text
requires_double_validation = false
```

Por lo tanto, el flujo V13.2.1 actual sigue siendo:

```text
Evidencia -> aprobación -> recompensa
```

La nueva política solo modifica campañas donde un Owner/Admin la active explícitamente.
