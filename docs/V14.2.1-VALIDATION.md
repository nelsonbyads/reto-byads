# DadoFit V14.2.1 — Admin Campaigns + Monetization Visual Hotfix

## Scope

This hotfix addresses only the two regressions observed after V14.2:

1. `/admin/campaigns` returned `structure of query does not match function result type`.
2. Personal pages wrapped by the global monetization shell exposed a dark document background around the ad rails and non-native ad artwork was cropped too aggressively.

No reward, auth, RBAC, challenge, evidence, organization or advertising business rules are changed.

## Apply

```bash
npx supabase migration list
npx supabase db push
npm test
npm run build
npm run dev
```

## Validation A — SuperAdmin campaigns

1. Login as the platform SuperAdmin.
2. Open `/admin/campaigns`.
3. Expected: no PostgreSQL result-structure error.
4. Existing sponsor campaigns should render with Brand, state, challenges, participants, approved/rejected, DC/XP and validation mode.

## Validation B — Personal background

With Appearance = Claro:

- `/challenges`
- `/gymbros`
- `/squads`
- `/organizations`
- `/sponsored-challenges`

Expected: the area around the ad rails uses the same light DadoFit background as the product. There must be no black canvas unless the user explicitly selects Oscuro.

With Appearance = Oscuro, the shell should still follow the real dark theme.

## Validation C — Advertisement artwork

Use the existing Nike campaign.

Expected:

- The placement still occupies 160×600 between 1600–1899px viewport widths.
- The placement still occupies 300×600 at >=1900px.
- Correct-format vertical art fills naturally.
- Square/landscape art is no longer cropped destructively; it is shown contained over a blurred full-bleed copy of itself.
- Brand/campaign CTA remains an overlay at the bottom.
- No empty lower half is introduced.
