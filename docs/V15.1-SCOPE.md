# DadoFit V15.1 — Reward Fulfillment + Compact Navigation

## Objetivo

Cerrar dos brechas detectadas durante la validación de V15.0:

1. evitar que el header personal se comprima en laptops/ventanas reducidas;
2. separar la referencia interna del canje del beneficio real entregado por el partner.

## Navegación

En Perfil Personal, `Entrenar`, `Retos` y `Premios` permanecen prioritarios. En resoluciones compactas se agrupan `Gymbros`, `Squads`, `Organizaciones` y `Patrocinados` dentro de `Más`.

No se reduce agresivamente la tipografía para ganar espacio.

## Fulfillment de Rewards

Cada oferta puede usar uno de estos modos:

- `shared_code`: un código promocional para todos los canjes;
- `code_pool`: inventario de códigos únicos, uno por canje;
- `redemption_url`: URL que se revela únicamente después del canje;
- `generated_code`: código interno generado por DadoFit, útil para pruebas o beneficios controlados por DadoFit;
- `instructions_only`: entrega física/presencial coordinada por instrucciones.

## Pool de códigos

El Owner/Admin puede pegar códigos separados por línea, coma o punto y coma, o importar un `.csv` / `.txt` desde el formulario.

Los códigos no utilizados no son visibles para Gymbros. En el canje, PostgreSQL toma un código `available`, lo asigna dentro de la misma transacción y pasa a `assigned`.

## Referencia vs beneficio

`redemption_reference` conserva el identificador DadoFit `DF-...` para auditoría.

`redemption_code` contiene el código promocional real cuando corresponde.

`redemption_url_snapshot` conserva el link real entregado al usuario cuando la recompensa funciona por URL.

## Seguridad

El débito de DadoCoins, la creación del redemption y la asignación del código ocurren dentro de `redeem_reward()`.

Si falta saldo, stock o un código disponible, la operación falla completa y no descuenta DC.

Los códigos del pool solo pueden ser consultados por Owner/Admin de la organización o SuperAdmin mediante RLS.
